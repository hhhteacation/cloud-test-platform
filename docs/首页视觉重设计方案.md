# 首页视觉重设计方案（桌面第一版）

## 1. 产品视觉判断

这不是一个销售型 SaaS，也不是数据大屏；它是 Android 真机视频 SDK 的**执行控制台**。首页首先要回答：

1. 现在有没有可用真机；
2. 当前/最近任务执行到哪一段；
3. APK、输入视频、SDK 处理与产物回收之间是否断链；
4. 失败发生在哪个真实执行阶段，以及下一步去哪里处理。

因此首页采用“实验室控制台 + 信号轨道”的表达，而不是常见的渐变 Hero、悬浮玻璃卡片和营销型数据卡。

## 2. 核心标志性视觉元素

**Device Signal Rail / 真机信号轨道**：把一次真实任务压缩为 `INPUT → ADB → SDK → OUT` 四段物理链路。

- 节点状态直接来自 `Task / DeviceRun / Device`；
- 完成、执行中、等待、失败使用形状、文字与颜色共同表达，不只依赖颜色；
- 运行时轨道出现克制的“信号扫描”运动；`prefers-reduced-motion` 下关闭；
- 设备、当前阶段、进度、最近事件和跳转执行现场在同一控制台内完成闭环；
- 后端断开时明确显示数据同步中断，不用模拟结果填充。

## 3. 视觉语言

- **色彩**：暖灰实验台 `#F3F1EA`、纸张白 `#FBFAF6`、近黑控制台 `#101712`、ADB/通过绿 `#19734B`、荧光信号绿 `#8DFF75`。警告与失败只在真实状态出现。
- **字体**：中文信息使用系统黑体保证可读性；阶段码、时间戳、设备状态使用等宽字体，形成“人类说明 / 机器信号”的双层语义。
- **布局**：左侧任务意图、右侧执行现场，比例约 40/60；用硬边框和连续分隔线组织信息，避免到处使用圆角卡片。
- **间距**：以 8px 为基础节奏，Hero 留出更大纵向空间，轨道节点保持均匀工程感。
- **交互**：主按钮创建任务；轨道控制台可直接进入当前任务；所有按钮保留键盘焦点和语义标签。

## 4. 模板化自检

以下常见 AI 落地页特征明确排除：

- 不使用紫蓝渐变、霓虹光晕、玻璃拟态背景；
- 不使用“标题 + 三张卖点卡 + 客户 Logo + CTA”的营销结构；
- 不用无业务意义的插画或抽象 3D 球体；
- 不把所有区域做成相同圆角、相同阴影的卡片；
- 指标不作为装饰性大数字，而作为任务/设备/通过率/超时的运行摘要；
- 核心视觉只能属于真机 SDK 执行平台：轨道节点、ADB 设备、阶段事件、产物回收均对应真实数据模型。

## 5. 第一版范围

- 桌面端优先，按用户当前要求暂不专门优化手机端；
- 保留现有 React、Vite、Ant Design、路由与数据客户端；
- 保留真实后端轮询与 Mock 显式演示模式；
- 信号轨道优先展示正在运行或排队的任务，空闲时展示最近任务；
- 完成后运行现有 Vitest、TypeScript/Vite 构建，并在本地浏览器进行桌面截图检查。
