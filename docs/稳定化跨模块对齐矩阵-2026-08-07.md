## 1. 结论口径

本文使用四种口径：

- **已确认事实**：可由当前代码、Git 状态、测试或已保存 Evidence 直接证明；
- **高概率判断**：与代码路径和历史现象高度吻合，但历史原始 Evidence 不足以完成唯一归因；
- **待验证假设**：必须通过 fixture 回放或真机运行确认；
- **建议决策**：下一阶段采用的架构或工程治理方向。

## 4. Profile / Controller / Coordinator 的目标职责

```text
Raw Window/XML/Package State
          │
          ▼
Observation Adapter
  只采集事实，不判断最终失败
          │
          ▼
Profile
  输出页面分类、风险等级和安全动作候选
          │
          ▼
Installation State Machine（唯一 Decision 所有者）
  结合历史状态、动作、时间、包状态判断下一步
          │
          ▼
Controller
  执行动作并返回动作结果，不自行决定业务终局
          │
          ▼
VerifyTransition
  Completed / Waiting / Unknown / Stalled / ManualRequired / Unsafe
```

### 有效进展不能只依赖节点 fingerprint

建议 `InstallProgressSignature` 至少包含：

```text
page classification
focused package/activity
关键 checkbox 状态
关键按钮 enabled/selected 状态
已执行动作及结果
package installed/version 状态
页面结构摘要
时间窗口和连续重复次数
```

判定规则：

- fingerprint 相同只表示“观察相似”，不直接失败；
- 任一业务字段变化都重置停滞计数；
- 点击后先进入 `WaitingForTransition`；
- 只有在限定时间内多次观察完全无业务进展，才进入 `Stalled`；
- unknown 页面在 grace 后重新采集和分类；
- 不安全或无法证明安全的页面进入 `ManualRequired/Unsafe`，不做通用文字或坐标点击。

## 5. 每个变更切片的强制对齐清单

一个变更只有同时回答下列问题，才允许进入机型验证：

1. **业务行为**：改变了什么；明确不改变什么；
2. **唯一所有者**：哪个深 Module 对最终结果负责；
3. **Interface**：调用者新增了哪些必须知道的规则，能否继续隐藏；
4. **状态**：Observation、Decision、Action 分别由谁产生；是否仍有第二个 writer；
5. **时序**：开始、等待、重试、超时、取消和清理的顺序；
6. **错误**：类别、置信度、可重试性、是否能覆盖既有成功证据；
7. **Evidence**：原始输入、观察、动作、输出、截断和决策摘要；
8. **测试**：Module 测试、跨 Seam 测试、fixture 回放、目标机和对照机；
9. **Git**：提交是否独立构建、测试和回退；是否依赖 untracked 文件；
10. **运行身份**：真机结果是否记录 commit SHA 和 dirty 状态。

在 S0 提交链、S1 真机 Gate 和 S2 状态机 Gate 完成前暂停：

- 继续新增非必要 OEM Profile；

- 增加新的启动 Probe 或并行判定路径；
- 仅通过扩大 timeout 处理误判；
- 通用 OCR、固定坐标或按文字盲点；
- 把当前 checkpoint 直接当发布基线；
- 与稳定化无关的大规模前端或平台扩展。
