## 6. S3：MorphoProtocolExecutor 收敛状态

### 6.1 已实现

`MorphoProtocolExecutor` 已集中拥有：

- 启动命令；
- Startup Observation 和原始 Probe Evidence；
- Logcat；
- 启动 Decision；
- 业务完成判断；
- `result.json` 解析；
- 输出发现和回收；
- 协议失败；
- 取消和清理。

`TaskOrchestrator` 不再直接解析 Morpho Probe 或持有 Morpho 专属布尔状态。

### 6.2 自动化边界

测试覆盖包括：

- Probe 完整、截断和命令失败；
- Process 存在、不存在和观察失败；
- 业务日志先于 Probe 成功；
- Logcat 失败但其他证据成功；
- 业务明确失败优先；
- `result.json` 空、损坏、字段非法和 taskId 不匹配；
- 输出缺失与输出观察失败分离；
- 取消、force-stop 和清理。

PKR110 能执行 Morpho，因此可作为当前 smoke/Gate 设备；这不能替代 V2324A 真机 Gate。

## 7. S4：Failure、Evidence 与兼容迁移

### 7.1 已实现

执行层已引入结构化 `ExecutionFailure`，包含：

```text
code
category
phase
retryability
confidence
message
evidenceRefs
```

兼容迁移保持：

- `TaskExecutionError` 旧 `code` 和 `message`；
- 数据库存储结构化 Failure/Evidence 信息，同时保留旧字段；
- API 同时暴露旧字段和新结构；
- Web 展示失败类别、阶段、置信度和 Evidence；
- 取消任务不继续采集设备状态；
- terminal failure Evidence 记录原始失败和附加采集结果。

### 7.2 Evidence 优先级

当前规则：

1. 业务明确成功不被低级诊断失败覆盖；
2. 业务明确失败优先于观察不完整；
3. 观察失败不能伪装成“未发现”；
4. 截图或 Logcat 辅助采集失败不改写已确认业务结果；
5. cleanup 失败作为附加失败，不无条件覆盖原始业务失败；
6. cancelled Attempt 不在取消后继续执行设备观察。
